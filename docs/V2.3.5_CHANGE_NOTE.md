# v2.3.5 change note

- Fixes the Windows matrix crash caused by passing `run_interval_bench.sh` directly to native `CreateProcess`.
- Launches every matrix child with `sys.executable` and `tools/interval_bench.py`, preserving the active Python environment on Windows and Linux.
- Makes `GOLD1_BENCH_THREADS` a genuine fixed maximum concurrency budget for Gold1, primecount, primesieve, and the optional fast-prime comparator.
- Replaces the hard-coded comparator calibration of sequential `12+12` versus concurrent `6+6` with budget-derived modes. At budget 4, those modes are sequential `4+4` and concurrent `2+2`.
- Records `thread_budget`, `thread_plan`, and exact selected mode labels in individual and aggregate outputs.
- Adds regression coverage for 2, 4, 6, 8, and 12-worker plans, odd budgets, stale mode rejection, comparator dispatch, and shell-free matrix child construction.
- Preserves the v2.3.4 Gold1 mathematical implementation, ten-case matrix, exact-validation gates, common-cutoff optimization, endpoint-specific safety fallback, and retry behavior.

This is a benchmark portability and resource-accounting correction. It is not a new theorem or evidence of performance on machines that have not been measured.
